# 百度 Web 服务 API 实测上限（圈见 · lib/baidu）

实测时间：2026-09-08，个人开发者服务端 AK，从本机直连 `api.map.baidu.com`。
所有数字都是**实测**而非文档抄录，作为 `lib/baidu/client.ts` 的默认参数依据。

## 1. 批量算路 `routematrix/v2/walking` —— 单次点对上限 = 100

| origins × destinations | 点对数 | 结果                             |
| ---------------------- | ------ | -------------------------------- |
| 1 × 10                 | 10     | status 0，返回 10 项             |
| 1 × 20                 | 20     | status 0                         |
| 1 × 50                 | 50     | status 0                         |
| 1 × 100                | 100    | status 0，返回 100 项            |
| 1 × 101                | 101    | **status 2「点对数量超出限制」** |
| 1 × 150                | 150    | status 2                         |
| 2 × 50                 | 100    | status 0，返回 100 项            |
| 2 × 51                 | 102    | status 2                         |
| 3 × 50                 | 150    | status 2                         |
| 4 × 25                 | 100    | status 0                         |
| 5 × 25                 | 125    | status 2                         |

结论：限制的是 **origins × destinations ≤ 100 对**，与 destinations 单独数量无关。
`ROUTE_MATRIX_MAX_PAIRS = 100`；分批策略：`dChunk = min(nDest, 100)`，`oChunk = floor(100 / dChunk)`，每批 ≤ 100 对。
返回 `result[]` 按 origins 外层、destinations 内层展开，`distance.value` 米、`duration.value` 秒。

单次请求耗时：≈ 0.9 s（10～100 对差别不大），所以点对越满越划算。

## 2. 并发 / QPS —— 401「当前并发量已经超过约定并发配额，限制访问」

| 并发数（无间隔连发 30 次） | 实际吞吐  | 401 次数   |
| -------------------------- | --------- | ---------- |
| 2                          | 2.2 req/s | 1 / 30     |
| 3                          | 3.3 req/s | 1 / 30     |
| 4                          | 4.1 req/s | 2 / 30     |
| 6                          | 6.1 req/s | 3 / 30     |
| 40（瞬时突发）             | —         | 约 30 / 40 |

串行（并发 1）以 2～10 QPS 间隔发送 12 次：全部 status 0（受 0.9 s 延迟限制，实际吞吐 ≈ 1 req/s）。

结论：401 是**并发配额**而非纯 QPS 配额，并发 ≥ 3 就稳定触发，并发 2 偶发。
默认值：`DEFAULT_CONCURRENCY = 2`，`DEFAULT_QPS = 3`（令牌桶），
再对 401/302/网络错误做指数退避重试（500 ms → 1 s → 2 s，最多 3 次，计入 `stats.rateLimited`）。
可用环境变量 `BAIDU_MAX_CONCURRENCY` / `BAIDU_QPS` 覆盖（企业认证 AK 可调大）。

## 3. 地点检索 `place/v2/search`

- `page_size` 上限 **20**：传 50 也只返回 20 条（`total` 字段仍给真实总数）。
- 多关键词用 `$` 拼接（如 `药店$大药房`），一次检索即可覆盖一个类别的所有 queries。
- `scope=2` 返回 `detail_info.tag`（如 `医疗;药店`），用于清洗与跨类别归属。
- 默认最多翻 3 页（60 条 / 类别）；10 个类别一次分析约 17 次检索、5 s 左右（并发 2）。

## 4. 地理编码 / 逆地理编码

- 传参 `location=lat,lng`（纬度在前），返回 `{lng, lat}`。
- 地理编码对**无法理解的地址**也会返回 `status 0` + 一个兜底坐标，
  靠 `comprehension === 0 && precise === 0` 判定为「未找到」→ `geocode()` 返回 null。
- 逆地理编码 `addressComponent.street` 可能为空，此时用 `town`（街道办）兜底。

## 5. 错误码约定

| status   | 含义                   | 处理                                         |
| -------- | ---------------------- | -------------------------------------------- |
| 0        | 成功                   | 写缓存                                       |
| 401      | 并发超限               | 退避重试                                     |
| 302      | 配额超限               | 退避重试（日配额耗尽时重试也无效，最终抛出） |
| 2        | 参数错误（含点对超限） | 直接抛出                                     |
| 4 / 5    | 配额 / 权限            | 直接抛出                                     |
| 240      | 服务禁用               | 直接抛出                                     |
| 其他非 0 | 失败                   | 直接抛出                                     |

`routeMatrixWalking` 对单批失败只把该批单元置 null，不向上抛；`attachWalkTimes` 再把 null 降级为估算并计 `stats.degraded`。

## 6. 一次完整分析的实测开销（人民广场，半径 1 km）

189 个 POI：地点检索 17 次（≈ 5 s）+ 批量算路 2 次 / 189 对（≈ 0.5 s），0 次 401，0 次降级；
同参数第二次全部命中缓存（17 次 cacheHits，磁盘缓存文件不含 AK）。
