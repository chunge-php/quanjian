# 圈见 · 开源治理

## 1. 维护者

| 角色       | 人员                                                    | 职责                                  |
| ---------- | ------------------------------------------------------- | ------------------------------------- |
| 核心维护者 | Ye Chun（[@chunge-php](https://github.com/chunge-php)） | 路线图、Review 与合并、发版、安全响应 |
| 贡献者     | 所有被合并 PR 的作者                                    | 记录于 GitHub Contributors            |

治理阶段：**单维护者（BDFL）阶段**。当出现连续 3 个月有实质贡献（合并 PR ≥ 5 个或主导一个模块）的贡献者时，由核心维护者邀请其成为共同维护者，并将本节更新为多维护者模式（见 §2.2）。

联系方式：drq.chunge.php@qq.com；安全问题按 [SECURITY.md](../SECURITY.md)。

## 2. 决策方式

### 2.1 日常决策

- Issue / PR 中公开讨论，默认 **惰性共识**：提案发出 72 小时内无反对即视为通过。
- 涉及 `lib/types.ts` 契约变更、评分模型、API 调用策略（影响配额）的改动，须先开 Issue 标注 `design`，写清动机与替代方案后再提 PR。
- 争议由核心维护者裁决，并在 Issue 中说明理由。

### 2.2 多维护者阶段（预设规则）

- 合并需至少 1 位非作者维护者批准；破坏性变更需全部维护者批准。
- 路线图版本范围每季度由维护者会议（异步 Issue 即可）确定。
- 维护者 6 个月无活动自动转为荣誉维护者，可随时申请恢复。

## 3. 发版流程

1. 确认 `main` 上 CI 全绿，`CHANGELOG.md` 的 `[Unreleased]` 已整理为本次版本内容。
2. 更新 `package.json` 的 `version`，将 `[Unreleased]` 改为 `[x.y.z] - YYYY-MM-DD` 并新增空的 `[Unreleased]`。
3. 提交：`git commit -m "chore(release): vx.y.z"`。
4. 打标签并推送：

   ```bash
   git tag -a vx.y.z -m "vx.y.z"
   git push origin main --tags
   ```

5. `.github/workflows/docker.yml` 自动构建镜像并推送到 `ghcr.io/chunge-php/quanjian:x.y.z`、`:x.y`、`:latest`。
6. 在 GitHub Releases 基于该标签创建 Release，正文粘贴 CHANGELOG 对应段落。
7. 版本号规则（SemVer）：`lib/types.ts` 或 `/api/analyze` 请求 / 事件格式不兼容 → major；新增功能 → minor；修复 → patch。0.x 阶段 minor 可包含不兼容变更，但须在 CHANGELOG 标注 `BREAKING`。

### 4.4 第三方服务

- **百度地图开放平台**：使用须遵守其 [服务条款](https://lbsyun.baidu.com/index.php?title=open/law)。本项目：① 不存储或再分发底图瓦片；② API 响应缓存仅用于本地加速，TTL ≤ 7 天，且不对外提供查询接口；③ 前端展示保留百度地图版权标识；④ 用户自行申请 AK，配额与费用由使用者承担。
- 使用者若将本项目用于商业服务，需自行确认百度地图商用授权。

### 4.5 依赖更新

- Dependabot 每周检查 npm，每月检查 GitHub Actions 与 Docker 基础镜像。
- 新增运行时依赖须在 PR 中说明：许可证、包体积、是否有活跃维护；禁止引入非 MIT / BSD / Apache-2.0 / ISC 许可证的依赖。
- 可用 `pnpm licenses list --prod` 复核。

## 5. 文档规范

- 所有文档中文，专业用语首次出现标注英文；命令、路径、文件名用代码格式并具体到可复制执行。
- 单个 Markdown 文件不超过 500 行，超过时按主题拆分并在文首互相链接。
- 技术数值以代码常量为准，文档只解释意图；数值变更时 PR 必须同步文档。
- 图用 Mermaid 内嵌，不依赖外部图床。

## 6. 长期维护承诺

- 大赛结束后仓库继续维护，路线图见 [ROADMAP.md](../ROADMAP.md)。
- 每个 minor 版本至少同步一次 Next.js / React 的安全补丁。
- 若核心维护者计划停止维护，将提前 3 个月在 README 顶部公告并寻找接手者；无人接手时归档仓库并保留所有文档与镜像。
